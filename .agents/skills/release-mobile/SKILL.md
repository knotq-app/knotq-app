---
name: release-mobile
description: Prepare and verify KnotQ iOS or Android releases without publishing them.
---

Use for mobile version bumps, release candidates, store artifacts, or release
triage. This skill prepares locally and stops before App Store Connect or Google
Play submission unless the user explicitly authorizes publication.

Workflow:

1. Identify both Git roots (`app/` and `app/mobile/`) and record clean/dirty
   state. Never overwrite unrelated mobile-shell or generated-binding changes.
2. Read the current version/build from the shell project and the release
   history. Confirm the generated UniFFI bindings are regenerated by the build.
3. Run the mandatory sync gates from `app/` before calling an artifact
   releasable. If the separate backend checkout or credentials are absent,
   report that boundary explicitly.
4. iOS: run the focused tests, the complete `KnotQMobileTests` target on a
   simulator, then archive/export only when requested. Preserve dSYM/UUID and
   archive paths for crash diagnosis.
5. Android: run Rust core tests, JVM tests, lint, connected smoke tests when an
   emulator is available, and assemble the requested ABI/artifact.
6. Verify version, architecture, symbols, entitlements, signing, and that no
   release job would publish automatically. Report exact artifacts and commands.

Do not use production data, delete app data, rotate store credentials, or submit
to either store as part of preparation. Store submission is a separate explicit
operation.
